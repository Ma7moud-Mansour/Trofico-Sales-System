# تطبيق التصميم المرجعي على نظام المبيعات

تم تحويل الصور الخمس إلى واجهات تشغيل داخل النظام القائم، مع الاحتفاظ بقواعد الطلب والمخزون والصلاحيات والبيانات المحفوظة.

## توزيع المرجع على الشاشات

| المرجع | التطبيق |
| --- | --- |
| الصورة 1 — لوحة المتابعة | قائمة كحلية يمين الشاشة، شريط بحث فعلي، بطاقات حالة صغيرة مشتقة من البيانات، مطلوب مني/كل الطلبات مع البحث والحالة، جدول إجراءات، وسجل نشاط جانبي |
| الصورة 1 — إنشاء الطلب | أقسام مرقمة، اختيار وبحث العميل، هاتف للعرض، عنوان خاص بالطلب، تاريخ، اختيار وبحث أصناف، أزرار زيادة وتقليل الكمية دون تقريب، وملخص وحفظ/إرسال |
| الصورة 2 — المراجعة | عنوان الطلب وملخص العميل والمندوب والتاريخ، مؤشر مراحل أفقي، بيانات إضافية قابلة للفتح، أزرار اعتماد/رفض لكل بند، سبب الرفض، وملخص مراجعة جانبي |
| الصورة 2 — المخزن | الأرصدة الفعلية والمحجوزة والمتاحة والعجز، تنفيذ البنود المعتمدة فقط مع بقاء المرفوض تاريخيًا، منع التأكيد عند النقص وملاحظة المخزن |
| الصورة 3 — الحركة | بطاقات إحصاء وتبويبات مراحل، جدول بعنوان العميل والسائق والحالة، تعيين/تغيير سائق من القائمة عبر لوحة جانبية، بدء التوصيل بتأكيد مستقل |
| الصورة 3 — الموبايل | تنقل سفلي، بطاقات الطلبات ومهام السائق، العنوان والكميات، اتصال بالعميل، نموذج مستلم وملاحظة، تأكيد كامل أو تسجيل تعذر |
| الصورة 4 — الحسابات | شاشة متابعة للقراءة، إجماليات مراحل حقيقية، المطلوب والمعتمد في الجدول، وتفاصيل كل طلب دون صلاحيات تنفيذ |
| الصورة 4 — العملاء | بحث وحالة وجدول، إضافة وتعديل عبر لوحة جانبية، وتعطيل يحفظ التاريخ |
| الصورة 4 — المنتجات | جدول المنتجات وإضافة/تعديل جانبي، يليه رصيد المخزون الفعلي والمحجوز والمتاح |
| الصورة 4 — المستخدمون | إدارة الحسابات والأدوار والتعطيل، مع عرض مقروء للصلاحيات الثابتة حسب الدور |
| الصورة 5 — الدخول | لوحة هوية كحلية وبطاقة دخول واضحة؛ اختيار حساب تجريبي بدل الادعاء بالتحقق من كلمة مرور |
| الصورة 5 — سجل العمليات | البحث والمنفذ ونوع الحدث والفترة، زر تفاصيل لكل حدث مع اسم المنفذ والطلب والوقت والتغييرات |
| الصورة 5 — الحالات | شارات المراحل والاعتماد الجزئي، حالات تحميل وفشل وتعارض، confirmations، الحقول المطلوبة، والملف الشخصي للعرض |

## القرارات التي تحافظ على المتطلبات

- لم تُضف أجراس إشعارات أو أزرار تقارير وإعدادات بلا وظائف؛ «مطلوب مني» هو المدخل التشغيلي الحقيقي.
- لوحة الهوية الكحلية ليست وضعًا داكنًا؛ مساحة العمل فاتحة.
- الحسابات لا ترى أرقام إيرادات أو تحصيل أو أسعار مخترعة.
- اختيار السائق لا يخرج البضاعة؛ الخروج يحتاج تأكيدًا منفصلًا ويستخدم أمر الصرف القائم.
- أزرار الكمية تعمل في المسودة فقط؛ المدير لا يغير requestedQuantity أثناء الاعتماد.
- عرض صلاحيات الدور للشرح فقط؛ لا توجد مصفوفة موافقات قابلة للتعديل خارج نطاق الإصدار.
- على الهاتف، الجداول العريضة محصورة داخل حاويات تمرير؛ الطلبات والتوصيلات تستخدم بطاقات.
- فتح وإغلاق اللوحات يستخدم Radix Dialog، مع focus trap وEscape واستعادة التركيز. الشريط السفلي له مساحة محجوزة حتى لا يغطي المحتوى.
- بيانات العميل القابلة للطي تبقى ظاهرة عند الطباعة. المسودة والسائق يبدآن ببيانات العميل مفتوحة.

## الملفات الرئيسية

- `src/app/reference-theme.css`: الهوية المرجعية، الكثافة، الشاشات المتجاوبة، واللوحات الجانبية.
- `src/components/app-shell.tsx`: البحث العام، القائمة، الحساب، والتنقل السفلي.
- `src/features/orders/operational-table.tsx`: قائمة الحركة والحسابات وبطاقات الهاتف وإجراءات التعيين والخروج.
- `src/features/orders/detail.tsx`: المراجعة والتجهيز والتوصيل الموحد ونموذج الهاتف.
- `src/features/orders/form.tsx`: النموذج والكميات وملخص الإرسال.
- `src/features/admin/pages.tsx`: إدارة البيانات وشرح صلاحيات الدور وتفاصيل الأحداث.
- `tests/e2e/reference-ui.spec.ts`: اختبار اللوحات الجديدة، التوصيل من الهاتف، ولقطات جميع الشاشات.

اللقطات النهائية في `docs/screenshots/reference-*`، ونتائج الفحوص في `TEST_REPORT.md`.
